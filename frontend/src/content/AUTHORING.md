# 互动课程的编写与发布

## 文件与职责

- `lessons/<slug>.json` 是互动内容的唯一来源；`journeys.ts` 自动发现这些文件。
- `LessonJourney.tsx` 负责渲染、反馈和结束页，不写具体章节文案或下载路径。
- 原课程正文、笔记和正式测验仍由后端提供。互动记录目前仅保存在本设备浏览器，不是正式成绩，不触发解锁、打卡、徽章或 SRS。

## 稳定身份

每课有 `slug`、递增的 `version`；每步有 `id`、`knowledgeIds`；每个答案字段和选项也有独立 ID。`correctOptionId` 引用同字段中的选项 ID，不依赖数组位置。

新增课时可以复制一份结构，然后编写内容。已经发布的 ID 不要因改标题、排序或格式而重新生成；改变概念语义时用新 ID。现有 knowledgeIds 为课程级标签，后续可细分误区，不能据此声称已实现知识点复习调度。

字段至少包含两个不同选项，每个选项都必须有针对性反馈。任务还需要目标、上下文、推理材料、正确后的解释与具体收获。表格数据可用 `table`，项目文件通过 `project.downloads` 和 `project.solution` 配置。下载文件必须位于 `public/practice/`。

## 版本与进度

内容或任务顺序发生改变时递增版本；旧版记录保留，新版从独立记录开始，暂不自动推断跨版本掌握。内容版本与记录格式以后都需要独立迁移设计，不能简单把数组下标当成题目身份。

v1 中的 `legacyTaskIds` 是本次整理之前的固定顺序快照，仅用于一次性理解旧式下标进度；不要调整顺序，也不要为新课编造迁移快照。原始旧键保留。旧版没有记录的首次作答不会补算为首次答对。

记录键为 `spark-quest:learning:<slug>:v<version>`。记录包含当前步骤 ID、完成步骤 ID、本轮 ID，以及每次回答的选项 ID、当时正确选项 ID、判断结果与时间。重新练习开启新一轮，保留该版本的旧回答；完成后证据只统计本轮。隐私模式/存储拒绝时可继续，无法保存时会提示。

## 发布检查

在 frontend 下运行：

```text
npm run check:content
npm run test:journey
npm run check:css
npm run build
```

`build` 已自动先执行内容检查。`releases.json` 记录已发布内容的版本和摘要；同版本修改会被阻止。完成内容与技术审查并递增版本后，执行：

```text
node scripts/check-journey-content.mjs --record-release
```

该命令也会检查旧摘要，不能借它绕过同版本修改规则。新课在首次记录前没有旧摘要，但仍必须完成审查。自动检查只能证明结构完整，不能证明答案、技术结论和干扰项优质。

浏览器回归先启动 `npm run preview -- --host 127.0.0.1`，再从项目目录执行 `python frontend/scripts/check-l2-journeys.py`。它从课程数据读取正确选项，验证交互流程，不能作为答案正确性的独立证据。Spark 示例的独立验证脚本仍保留在 backend 下；Windows 文件写出限制见项目变更记录。

## 推广边界

后续章节先沿用选择推理与多字段补全。确实需要新交互时再扩展内容协议，不要根据章节标题在播放器中分支。异题补救、延迟复习、跨设备记录同步和课末测验重编属于后续工作，本轮没有启用。


## 按需引用旧正文

`task.reading` 可关联本课 explanation 的一段原文，包含稳定 id、入口 title、startMarker/endMarker，以及互动结果与概念的 connection 和经过核对的 boundary。正文由 API 提供，禁止再把引用段落复制进 JSON 形成第二份知识来源。Shuffle 五个步骤现已全部关联；sectionTitle 可标记实际引用的是人话理解、心智模型、技术定义或内部执行等段落。

构建检查 seed 中的标记，运行时检查 API 的实际正文；原文漂移无法匹配时提供完整参考入口，不静默显示另一段。引用中技术简化或误导性的比喻必须配边界说明。打开辅助阅读不算答错、不加分，也不证明掌握。
