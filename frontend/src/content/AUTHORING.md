# 互动课程的编写与发布

## 文件与职责

- `lessons/<slug>.json` 是互动内容的唯一来源；`journeys.ts` 自动发现这些文件。
- `LessonJourney.tsx` 负责渲染、反馈和结束页，不写具体章节文案或下载路径。
- 原课程正文、笔记和正式测验仍由后端提供。互动记录目前仅保存在本设备浏览器，不是正式成绩，不触发解锁、打卡、徽章或 SRS。

## 稳定身份

每课有 `slug`、递增的 `version`；每步有 `id`、`knowledgeIds`；每个答案字段和选项也有独立 ID。`correctOptionId` 引用同字段中的选项 ID，不依赖数组位置。

新增课时可以复制一份结构，然后编写内容。已经发布的 ID 不要因改标题、排序或格式而重新生成；改变概念语义时用新 ID。现有 knowledgeIds 为课程级标签，后续可细分误区，不能据此声称已实现知识点复习调度。

字段至少包含两个不同选项，每个选项都必须有针对性反馈。任务还需要目标、上下文、推理材料、正确后的解释与具体收获。表格数据可用 `table`，项目文件通过 `project.downloads` 和 `project.solution` 配置。下载文件必须位于 `public/practice/`。

## 版本与进度

内容或任务顺序发生改变时递增版本；旧版记录保留，新版从独立记录开始，暂不自动推断跨版本掌握。内容版本与记录格式以后都需要独立迁移设计，不能简单把数组下标当成题目身份。

v1 中的 `legacyTaskIds` 是本次整理之前的固定顺序快照，仅用于一次性理解旧式下标进度；不要调整顺序，也不要为新课编造迁移快照。原始旧键保留。旧版没有记录的首次作答不会补算为首次答对。

记录键为 `spark-quest:learning:<slug>:v<version>`。记录包含当前步骤 ID、完成步骤 ID、本轮 ID，以及每次回答的选项 ID、当时正确选项 ID、判断结果与时间。重新练习开启新一轮，保留该版本的旧回答；完成后证据只统计本轮。隐私模式/存储拒绝时可继续，无法保存时会提示。

## 发布检查

在 frontend 下运行：

```text
npm run check:content
npm run test:journey
npm run check:css
npm run build
```

`build` 已自动先执行内容检查。`releases.json` 记录已发布内容的版本和摘要；同版本修改会被阻止。完成内容与技术审查并递增版本后，执行：

```text
node scripts/check-journey-content.mjs --record-release
```

该命令也会检查旧摘要，不能借它绕过同版本修改规则。新课在首次记录前没有旧摘要，但仍必须完成审查。自动检查只能证明结构完整，不能证明答案、技术结论和干扰项优质。

浏览器回归先启动 `npm run preview -- --host 127.0.0.1`，再从项目目录执行 `python frontend/scripts/check-l2-journeys.py`。它从课程数据读取正确选项，验证交互流程，不能作为答案正确性的独立证据。Spark 示例的独立验证脚本仍保留在 backend 下；Windows 文件写出限制见项目变更记录。

## 推广边界

后续章节先沿用选择推理与多字段补全。确实需要新交互时再扩展内容协议，不要根据章节标题在播放器中分支。课末测验已接入独立分用途题库；课中异题补救先在 L2 五个误区试点。延迟复习的细粒度调度与跨设备互动记录同步仍未启用。


## 按需引用旧正文

`task.reading` 可关联本课 explanation 的一段原文，包含稳定 id、入口 title、startMarker/endMarker，以及互动结果与概念的 connection 和经过核对的 boundary。正文由 API 提供，禁止再把引用段落复制进 JSON 形成第二份知识来源。Shuffle 五个步骤现已全部关联；sectionTitle 可标记实际引用的是人话理解、心智模型、技术定义或内部执行等段落。

构建检查 seed 中的标记，运行时检查 API 的实际正文；原文漂移无法匹配时提供完整参考入口，不静默显示另一段。引用中技术简化或误导性的比喻必须配边界说明。打开辅助阅读不算答错、不加分，也不证明掌握。


## 可选异题补救（五个误区试点）

`task.remediation` 是一条同知识点的新材料小题：id、knowledgeId、title、intro、code、prompt、单字段 field 和 insight。每个选项仍需独立反馈，正确答案使用稳定选项 ID。新材料不能只复制原题，需让学习者迁移同一判断；构建检查只查结构与文本不同，创作时还要核对概念一致和唯一可答。

原题答错后可选进入，或直接重试原题。补救错答可再试，答对后回原题重新选择；补救不完成步骤、不记正式分数、不触发解锁或 SRS。activity=remediation 的本机记录包含补救 ID、知识点 ID 与答案快照，原题次数排除这些事件。刷新会返回原题，已经提交的记录保留；不保存补救界面的临时选择。

本轮覆盖 NULL 筛选、when 空值分支、去重保留规则、count 对象和 avg 分母；涉及四课从 v2 升 v3，稳定主任务/选项 ID 保持，v2 本机记录仍在旧键下，v3 独立开始。当前每个试点只有一道补救，未实现按错误选项自动选择多套题，也未接入后台那 20 道 remediation 用途题。新增试点运行 `python scripts/check-inline-remediation.py`（先启动预览），检查失败重试、回原题、记录隔离与响应式。


## 隔天验证（五个知识点试点）

`delayedChecks.json` 独立管理题源与版本，构建检查纳入 releases 摘要；修订材料需升版本并为变更题使用新 ID，避免旧证据套在新内容上。每题关联 lesson slug、稳定 taskId 与补救 knowledgeId，材料须不同于原题和课中补救。当前每知识点一道独立新情境，不能据此宣称长期掌握。

只有当前版本原步骤已完成且有原题正确作答事实，才进入候选。以该步骤最近一次原题/补救作答为起点，满 24 小时后显示入口。新作答会重新推迟安排。验证前不显示答案/讲解，提交后显示反馈；正确材料收起，直到后续再次接触原题；错误至少 24 小时后才再试，重试材料相同，不能当作全新独立证据。

记录键 `spark-quest:delayed:v1` 保存 itemId/sourceAt、所选和当时正确选项、正确性与时间，不写原进度或后台。提交时重新计算到期安排，拦截重复提交、过期页面与其他标签页已处理的题。存储异常不伪造成功、不覆盖坏记录；页面明确提示读取/保存失败。首页每分钟及窗口聚焦/存储事件刷新入口。课末说明明天在哪里继续，直接路由 `/delayed-check` 也可进入。

运行 `python scripts/check-delayed-checks.py` 检查受控时钟下的首页入口、五题反馈、刷新续答、24 小时重试、原记录不变、陈旧提交和存储拒绝，配合单测测试精确到期边界。脚本不连接学习数据库，也不能替代 Spark 示例验证或真实教学效果评估。未接入系统通知、跨设备同步、课程级 SRS、正式成绩或连续天数。


## 标准讲解与历史原文

L2 使用 `standardGuides.json`（独立版本与发布摘要）提供当前标准讲解，十课 41 节按主任务稳定 ID 关联。每节包含 title/body/boundary；题中阅读与整课标准讲解从同一节内容渲染，禁止另复制一份正文。内容检查要求覆盖全部 L2 步骤并有官方来源。题目版本和答案未改变时，不为讲义编辑清空或迁移互动进度；修改标准讲解需增加其独立版本。

`JourneyReading` 收到标准章节时默认展示标准说明与边界，答对后的概念联系仍保留。旧 reading 标记保留，用于展开“对照历史原文”；片段仍从 API explanation 提取，定位漂移明确提示。`#lesson-reference` 打开完整标准讲解；`#lesson-original` 打开完整历史原文与旧示例、要点和勘误。标准讲解没有替换数据库原内容，也没有更改笔记 API；笔记仍在独立入口。没有标准讲解的 Shuffle/L7 继续沿用原阅读流程。

原文勘误只在历史内容附近展示，避免默认学习时把正确讲解与错误旧口径并排。历史档案并不代表旧内容重新获得技术认证；标准讲解也仍需实作和学习效果验证。`check-linked-readings.py` 覆盖标准节、历史引用、两类全文跳转、阅读不改变进度、答错/答对分支及手机显示。


## 独立毕业任务

`capstones.json` 为独立任务协议，目前用于 L2 综合课：任务摘要、交付约定、下载包、验收命令、检查维度和逐级提示。`CapstoneProject` 是默认入口；旧 LessonJourney 保留在可选准备练习里，旧任务/选项 ID、题目版本与作答事实不变。新任务使用另一份数据，不能把准备练习中已经展示的数值当成毕业任务答案。

当前四步为接任务、预测/计划、运行验收、复盘对照。提示按需逐级展开，参考下载另外确认展开；不在默认 README/starter 中给出完整数值答案。草稿为独立 `spark-quest:capstone:<id>:draft` 本机记录，明确手动保存且不代表验收通过；未实现代码编辑器、浏览器执行、本地结果上传认证或新的正式成绩门槛。

`public/practice/l2-graduation` 包含新 CSV、三个函数的 starter、独立 verify、README 和 reference。验收器用 Python 标准库推导期望值，检查真实 Spark 输出，不调用 reference 生成答案。查询与文件阶段分开，--query-only 输出 PARTIAL；默认模式必须实际 CSV 读取、Parquet 写出/读回与同批重跑全部通过才输出 PASS。输出只在临时目录，JSON 结果写到用户当前目录或 --result 指定路径，不连接学习数据库。

构建检查将 capstones 配置和所有下载文件的摘要一起锁定到 releases；修改工具包也需增加独立 capstones 版本，改变任务约定时另换 id 保留旧草稿。浏览器检查 `python scripts/check-capstone-ui.py`；Spark 反向校验 `python scripts/check-capstone-verifier.py`，拒绝总额正确但地区错误、漏去重、错误单位/类型、重复结果、硬编码旧答案与提前清洗原始输入等错误。

开发机 PySpark 4.2.0 五组查询已实跑，七项错误结果拒绝检查通过，CSV 读取也已验证；Parquet 提交仍因 Windows NativeIO$Windows.access0 缺失失败。不能把它写成完整实作验收通过，仍需在文件系统支持完整的 Spark 环境补验。版本兼容性没有据此扩展到所有 Spark 发行版。


## L3 整章编写源

`frontend/scripts/author-l3-content.py` 是九课显式编写源，`--check` 比对输出、不写文件。普通运行生成九份 v1 lesson，并以稳定 ID 合并标准讲解和延迟题；已有 L2 条目保留。它不是自动按标题填词的出题器，每题有具体材料、逐项反馈、语义收束与适用边界。

标准讲解、延迟题与毕业配置分别为独立 v2；L3 旧数据库阅读不冒充互动迁移记录。新课不要编造 legacyTaskIds。两章共用 CapstoneProject，SQL 任务的 build_report 接收 spark 和本次 orders，参考实现每次替换自己的视图，避免复用前一输入。

L3 38 步/9 补救/9 延迟的原文与代码均经结构检查及浏览器回归；`check-l3-examples.py` 独立实跑关键语义与六种错误报告。验收不认证所有干扰项质量、所有 Spark 版本或长期学习保持。正式题源的 34 项纠错与既有库升级说明见根目录 L3_ROLLOUT_PLAN.md。


## L4–L6 批次与按需加载

`author-l4-l6-content.py` 显式编写 27 课/115 步，包含保留的 Shuffle 五步，其他为新 v1。Shuffle 因增加补救升 v4，主步骤/选项 ID 与原题内容保持，v3 本机记录仍在原键；按既有策略新版独立开始，不伪造跨版本成绩。L3 作者脚本改为保留后续版本与统一延迟顺序，双方 --check 均可重复验证。

标准讲义/延迟题库/毕业配置升独立 v3。L3–L6 共36课，每课一个补救/隔天重点，并非每一步都有自适应分支。合成指标与简化计划明确标记，不能当真实基准。

`journeys.ts` 按 slug 动态加载当前课完整内容；`journeyIndex.json` 是构建检查派生的轻量版本/任务 ID 索引，供首页和延迟调度使用，不含答案字段。内容通过审查后用 --record-release 同步索引；普通构建检测索引漂移而不静默重新解释旧进度。`loadProgress` 接受最小元数据，单测对照完整课和索引确保记录一致。LessonPage 切换路由取消旧请求，避免慢响应覆盖新课程。

L4–L6 毕业任务下载 kit 分别使用 task.json，`lab-verifier-template.py` 为三份独立 verify.py 的共同源。任务目标是计划、分区或连接证据，不伪装成 Parquet 读写认证；自动 PASS 与人工诊断 review 明确分开。不要随意改已发布下载资产；内容摘要同时锁定配置和资产。

正式题源 `backend/app/l3_l6_reviewed_bank.json` 由显式作者脚本产生，36 课各 5 assessment +3 review +2 remediation；服务端两种五题组隔离。180 组目标两份材料不等于360个新概念，答案长度/位置指标不等于教学质量证明。原题保留历史，并未重新认证所有旧文本。


## L1/L7 与全七章复核

`author-l1-l7-content.py --check` 比对显式15课/66步内容；`author-l1-l7-labs.py --check` 比对两个新工具包及五份共用验收器。当前标准讲义/延迟题为v4，毕业配置为v5，互动61课/260步。L7样板六步主内容逐项保留，增加辅助内容后v2独立记录，不迁移伪造掌握。

`backend/author_reviewed_l1_l7.py --check` 维护150题，原题追加保留，通用 `install_reviewed_bank.py` 默认只预览；`--apply` 先备份再安装。`audit_preservation.py <backup>` 只读逐行比对旧题与全部非题目表。题池边界用独立SQLite内存库测试，不写用户库。

L1任务明确空白分词、小写、标点保留、不去重；L7任务明确ASCII空格trim、NULL与空串语义。实际计划去掉Python UDF只证明受控结构变化，不能宣传固定加速。`diagnosis()`非空仅表示提交草稿，质量仍人工待审。完整验证边界和下一步内容工作见根目录 FINAL_CURRICULUM_REVIEW.md。

下载工具包受字节摘要约束，`.gitattributes` 强制 LF，作者脚本写出也须指定 LF。构建会拒绝文本资产 CR，防止 Windows 正常而 Linux 发布误报漂移。


## 概念递进修补层

三个分章作者在基线输出前调用 `concept_progression.apply`。它显式定义26课的修订版本、14个新增步骤、术语解释和章首/章末桥接；以稳定bridge- ID合并，可重复运行。`concept_progression.py --check` 比对全层，分章作者 --check 必须同时保持通过。不要绕过修补层在JSON临时改字，再让旧作者覆盖。

当前标准讲解v5、延迟库v5、毕业配置仍v5；各课版本独立。总计61课/274步、57个补救/延迟目标。旧任务题干、代码和答案身份保留，新版互动独立计进度，旧本机记录不删除，数据库正式成绩不重置。新内存规则未改动正式题库，课中与隔天检查不能冒充新增正式覆盖。

容量题为明确简化的总体模型，不预测单Task的精确配额。`check-concept-examples.py` 分开检查模型数字与真实Spark的有限内存管理行为，不模拟真实缓存块逐出。见根目录 CONCEPT_PROGRESSION_REPAIR.md。
